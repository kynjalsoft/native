# ZyndMail iOS and Android release

The authoritative signed build pipeline is EAS Build. The app uses the existing ZyndMail application IDs (`io.zyndpay.mail`), EAS project `e9054c93-18de-4d6a-bc34-38c020130b82`, and production update channel. The former Preview-specific GitHub Actions release workflows have been removed. CI still checks source and native compilation.

`ios/` is generated by Expo prebuild and is not committed. Keep native iOS permissions, entitlements, and plugins in `app.config.js`. `android/` is committed, so review native changes there alongside the Expo config.

For an internal iOS TestFlight candidate, build the clean reviewed commit with `eas build --platform ios --profile production --non-interactive`. Confirm the returned build ID, version, bundle ID, source commit, signing team and successful status. Submit that exact ID using `eas submit --platform ios --profile production --id BUILD_ID --non-interactive`. The App Store Connect app ID is `6815344620`. Wait until Apple lists the new build as processed and available to the existing internal team before telling testers to install it. This is not a public App Store release.

For Android, `eas build --platform android --profile production` creates a signed AAB for a future Play release. `eas build --platform android --profile production-apk` creates a signed installable APK on the same production channel. The APK build must receive the production Firebase file from EAS and must have package `io.zyndpay.mail`; neither artifact is a Preview build. Do not submit the AAB to Play without a separate public-release decision.

Expo OTA updates are JS/assets only. Publish to the production branch with `eas update --branch production --environment production` from an exact clean merged commit, and verify the iOS and Android update IDs and runtime `0.3.0` match their installed binaries. Native changes require a new signed build. Check automatic update application on physical devices in an idle mail view, and confirm compose/drafts do not reload underneath the user.

See [zyndmail-production-release.md](zyndmail-production-release.md) for migration, push, device and source-license acceptance gates.
